## 2. 镜像烧录（新板/换卡/恢复出厂必做）

**准备**：读卡器 + 8G 以上 SD 卡（建议 32G）+ 电脑。⚠️ 烧录会格式化卡，先备份。

1. **格式化**：装 SD Card Formatter → 选择 SD 卡盘符（不确定就先拔卡看盘符变化）→ Format → 确认。
2. **烧录**：打开 Rufus → 选择 SD 卡盘符 → 选择镜像 `CanMV_K230_Hiwonder_micropython_local_nncase_v2.9.0.img` → 点"开始" → 确认 → 等待完成 → 关闭。
3. **上板**：SD 卡插入开发板 → Type-C 连电脑 → 电脑出现 `CanMV` 盘符即启动成功。

### 系统盘结构（上电后电脑可见）
```
CanMV/
├── sdcard/     # 板内 /sdcard —— 库文件、官方示例、你的 main.py、模型、素材
└── data/       # 板内 /data   —— 用户剩余空间
```

> 如果电脑看不到 CanMV 盘符：换数据线、检查 SD 卡是否插好、重新烧录。

## 3. 串口驱动与 IDE 安装

### 3.1 串口驱动（CH340）
- 直接用 Type-C 连电脑，打开"设备管理器"看端口：**能识别到串口就不用装驱动**。
- 装：`2.3 串口终端工具/` 里的安装包，双击 → 安装 → 等提示成功。

### 3.2 CanMV IDE 安装
1. 双击 `canmv-ide-windows-4.0.9.exe` → 安装 → 选路径 → 完成。
2. 打开 CanMV IDE。

### 3.3 IDE 界面速记
| 区域 | 说明 |
|---|---|
| 菜单栏 | 文件 / K230 烧录工具 / **视觉相关工具（阈值编辑器、AprilTag 生成器）** |
| 快捷按钮 | 常用操作 |
| 代码编辑区 | 写 MicroPython 的地方 |
| 设备连接区（左下） | 上=连接/断开设备；下=运行(绿三角)/停止 |
| 调试信息区（右下） | 串口打印输出（你的 `print` 在这里看） |
| 图像参数区 | 上方图像预览（IDE 虚拟显示模式画面就在这里），下方色彩参数 |
| 固件信息 | 串口号与固件信息 |

## 4. 连接开发板（失败率最高的环节）

1. 用 **Type-C 数据线**把开发板连到 PC（⚠️ 充电线没有数据线芯，一定用数据线；出厂附的是数据线）。
2. CanMV IDE → 点左下角连接按钮 → 10 秒内连上，左下角变为绿色（运行中为另一种状态）。
3. **连接失败排查**：
   - 换一根确认能传数据的 Type-C 线；
   - 板子烧了其它固件 → 重新烧官方镜像；
   - 换个 USB 口（优先主板直出，不用 hub）；
   - 查看设备管理器是否出现串口/USB 设备。

## 5. 程序运行：在线运行 vs 脱机运行

### 5.1 在线运行（开发调试首选）
1. 把 `.py` 文件拖进 IDE 代码编辑区（或直接粘贴代码）。
2. 点左下角**运行**按钮。
3. 程序跑在板子上，终端打印在 IDE 右下；画面（IDE 虚拟显示时）在右侧预览区。
4. 点**停止**或 `Ctrl+C` 结束。
> 在线运行的程序**断电即丢**，不保存。

### 5.2 脱机运行（交付/量产）
1. 在线调好后：IDE 菜单 **工具 → "保存当前打开的脚本为（main.py）到CanMV Cam"**。
2. 弹窗点 **Yes** → 提示成功 → OK。
3. 之后**只给板子上电**（不连电脑），板子自动运行 `main.py`。
> 想更换/停用：把板子当 U 盘，覆盖/删除 `CanMV/sdcard/main.py`。
> 如果脱机程序是死循环且想重新接管：上电瞬间按 Ctrl+C（REPL 方式）或直接删 main.py。

### 5.3 三种文件传输方式
| 方式 | 做法 | 适用 |
|---|---|---|
| 拖进 IDE | 直接把 .py 拖入 CanMV IDE | 单文件脚本 |
| 复制到盘符 | 资源管理器打开 `CanMV/sdcard/` 粘贴（模型、图片、音频、多文件项目） | 资源文件/整包 |
| 脚本内读写 | 板端代码里 `open('/sdcard/xxx','w')` 自己生成 | 日志、录音、拍照 |

**路径映射（写到代码里用左列，拷文件用右列）**
```
板内 /sdcard/xxx      ←→   电脑 CanMV/sdcard/xxx
板内 /data/xxx        ←→   电脑 CanMV/data/xxx
```

## 6. REPL 串口交互（进阶调试）

1. 板子连 PC，设备管理器查到串口号（如 COM30）。
2. 打开 PuTTY：Connection type = **Serial**，Serial line 填串口号，Speed = **115200** → Open。
3. 按回车出现 `>>>` 即成功；可直接敲 Python 语句（如 `print("Hello")`、`1+1`）。
4. 若按回车没有 `>>>`：板子在跑死循环 → 按 **Ctrl+C** 打断。
> 大多数情况下用 IDE 自带的终端就够了，REPL 适合"板子跑飞了"的急救。

## 7. 显示模式切换（每个视觉程序开头的配置）

| 模式 | `select_display` | Display.init 参数 | 分辨率 | 适用 |
|---|---|---|---|---|
| HDMI | 1 | `Display.init(Display.LT9611, width=, height=, to_ide=True)` | 默认 1920×1080（**必须匹配你的显示器，否则可能跑死**） | 接 HDMI 显示器 |
| LCD | 2 | `Display.init(Display.ST7701, to_ide=True)` | 800×480 固定 | 套件的 3.5 寸触摸屏 |
| IDE 虚拟 | 3 | `Display.init(Display.VIRT, width=, height=, fps=, to_ide=True)` | 自定（常用 640×480 / 800×480 / 1280×720） | **没屏幕时首选**，看 IDE 预览区 |

> AI 例程里通常还有 `display_mode_map = {1:"hdmi", 2:"lcd", 3:"ide"}`，把数字转成 `PipeLine` 需要的字符串模式名。

## 9. 常见运行错误与其含义（快速对照）

| 现象 | 原因 | 处理 |
|---|---|---|
| 连接按钮一直转圈/失败 | 充电线 / 固件不对 / USB 口问题 | 换线、重烧固件 |
| 运行后 IDE 无任何输出 | 没连上就点了运行 / 程序在初始化卡住 | 先连接再运行；加 print 定位 |
| `ImportError: no module named 'xxx'` | 板端没有该库（libs 缺失或路径错） | 检查 /sdcard/libs；AI 例程需要官方镜像自带 |
| `OSError: [Errno 2] ENOENT` | 文件/模型路径不存在 | 核对 /sdcard 下的实际文件名 |
| `MemoryError` | 内存不足（大分辨率 + 大模型） | 降分辨率、gc.collect()、换小模型 |
| 画面冻结/花屏/跑死 | 显示分辨率不匹配 / 资源未释放 | 按 §显示模式 检查；遵守释放契约 |
| 第二次运行必挂 | 上次没释放 Sensor/Display/Media | 用 try/finally 完整释放（见 SKILL §5.3） |
| 摄像头报错/无图 | 排线松动 / 被占用 | 断电重插 FPC；确认没有其它程序占用 |

## 10. agent 工作流模板（推荐按此推进）

```
1. 读需求 → 在 ref/12-example-index.md 找最接近的官方例程
2. 读该例程源码（资料包内路径）→ 确认 API 与初始化顺序
3. 在 projects/<项目名>/main.py 写代码：
   - 顶部配置区（select_display / 阈值 / 路径 / WiFi）
   - 主体逻辑（照抄例程结构，改参数与逻辑）
   - try/finally 资源释放
4. 写 README.md：功能 / 接线 / 运行步骤 / 需拷贝的资源
5. 告诉用户：「把 main.py 拖进 CanMV IDE → 连接 → 运行」→ 根据回报的终端日志迭代
6. 调通后指导用户：「工具 → 保存为 main.py 到 CanMV Cam」完成脱机部署
```

**给用户的操作指令要具体到菜单名**（例：`点击 CanMV IDE 左下角的连接按钮`），因为很多用户不熟悉 IDE。
