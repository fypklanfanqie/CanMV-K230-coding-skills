2.1 FPIOA实验说明
 
2.1.1 实验简介
 
本节通过程序学习FPIOA，进行配置物理引脚。FPIOA（引脚复用器）模块主要负责配置物理引脚（PAD）的功能。在 
SoC 中，尽管可用功能多种多样，但由于引脚数量有限，多个功能可能会共享同一个 I/O 引脚。此时，每个引脚在同
一时刻只能启用一种功能，因此必须通过 IOMUX（即 FPIOA）来选择并激活合适的功能。
2.1.2 准备工作
 
模块连接
1. 使用Type-C数据线将K230开发板连接到PC端，如下图所示：
2. 双击打开CanMV IDE K230；
3. 点击左下角的连接按钮；

4. 连接成功，CanMV IDE软件左下方会变为下图所示图标。
5. 若连接超过10s，则为连接失败，点击“取消”按钮，会出现以下弹窗，点击“OK”。重新检查连接。
 
Note
连接失败原因及其解决方法：
连接线不是数据线：有Type-C线为充电线，没有数据传输功能，请使用有数据传输功能的Type-C线进行连
接（我司出厂配备的为Type-C数据线）。
烧录了其他的K230固件：重新烧录出厂固件，之后进行连接即可。

2. n = 16 - (len(data) % 16)  计算出需要补充多少个字节才能使数据的长度变为16的倍数。
3. data + bytes([0]*n) 将n个0x00字节添加到明文数据的末尾，从而使长度符合AES算法的要求。
4. 在解密时，解密后的数据可能会包含原始数据末尾的补齐字节（0x00）。unpad函数用于去掉这些多余的字节，
恢复原始数据。rstrip(b'x00') 会去掉数据末尾的所有0x00字节，这是对补齐的反向操作。

2.15.5 程序分析
 
写文件操作
定义文件路径然后使用 open  函数打开指定路径的文件，模式为 'w'（写入模式）。如果文件不存在，会自动创建它。
如果文件已经存在，'w' 模式会清空文件内容并重新写入。
读文件操作
这行代码再次使用 open  函数打开文件，这次是以 'r'（读取模式）打开文件，content = f.read() 并存储在 
content  变量中。f.read()  会将文件中的所有文本作为一个字符串返回。然后进行打印。
file_path = '/sdcard/data_log.txt'
# 写文件，使用with结构自动管理文件关闭
with open(file_path, 'w') as f:
    f.write('hello hiwonder')
# 读文件，使用with结构，避免忘记关闭
with open(file_path, 'r') as f:
    content = f.read()
    print(content)
